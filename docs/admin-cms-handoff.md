# Admin content management handoff

## Scope

This is a frontend UI/UX prototype, not a deployed CMS. Content editors demonstrate draft saving, content review and a confirmed prototype publish action. Drafts and the last ten prototype releases are held in this browser. The homepage reads locally published releases in the same browser on page load. Drafts are excluded from normal homepage visits. Other visitors are unaffected. Authentication, uploads, submissions and payments are not implemented backend services.

The public site remains a Vite/React/TypeScript multi-page static site. Do not add a routing framework. Admin navigation uses `#workspace/page/section`, for example `/admin/#service-pages/cybershield/header`; browser back/forward and direct entry must work. The in-app **Pages & API map** is the clickable coverage directory.

## Frontend ownership

- `adminSections.ts`: sidebar workspaces and grouping.
- `adminLocation.ts`: URL subscription and navigation; URL is the source of truth.
- `cms/editors.ts` and `extendedEditors.ts`: editor schemas, relationships and initial data.
- `cms/pageContext.ts`: source-derived fixtures for inner page sections and media.
- `content/admin-page-context.json`: current public-page context, generated by `node scripts/extract-editor-context.mjs`. This is a handoff fixture, not a runtime scraper or backend.
- `cms/ContentEditor.tsx`: section editing, repeatable records, save/discard and draft state.
- `cms/HomePreview.tsx`: renders the actual homepage in an isolated iframe, with desktop/mobile widths and the selected section anchor. A temporary sessionStorage snapshot includes unsaved edits for Preview; publish confirmation includes saved drafts only.
- `content/homepageDemo.ts`: combines homepage defaults, local releases and an optional preview snapshot. Shared testimonials and logos retain their canonical collection keys.
- `cms/TextEditor.tsx`: lightweight paragraph editor supporting bold, italic and bullets; `FormattedText.tsx` renders this limited markup safely without HTML injection.
- `cms/ContentReview.tsx`: textual content review for the remaining inner-page prototypes.
- `cms/prototypeStore.ts`: replace this local adapter with HTTP integration. Never treat browser storage as shared production persistence.
- `cms/ContentMapView.tsx`: page coverage and proposed endpoint list.

## Pages and reusable records

Homepage owns hero, alliances introduction, company introduction, service highlights, contact introduction, client introduction and testimonial introduction. Partners, clients and testimonials are shared collections referenced by ID. About Us covers Who We Are, How We Do It, Why We Do It, Board and Team. Alliances and Clients currently link to homepage anchors rather than separate public pages.

Our Services covers Consultancy, Managed Services, Training, Cybershield, Automation Tools and Rwanda DPP Registration. Resources covers Shop, Blog, SDG Commitment and Travel Advisory page content. Careers covers recruitment and Talent Shield. Upcoming and FAQ have authoring designs but their public pages are not yet built. Preserve that distinction when integrating.

Maintain articles, people, alliance/client organisations, testimonials, courses, events/sessions, products and jobs once. Products reference courses; sessions reference courses; bookings reference sessions. Keep incoming feedback private until editorial approval and publication permission create a testimonial. Keep job applications and Talent Shield applications in separate workflows.

## Proposed content API

All admin endpoints require an authenticated staff session and server-side role checks. Use Editor (save drafts), Publisher (publish/restore) and Administrator (accounts/settings). Public reads must never expose drafts or private submission data.

| Method               | Endpoint                                         | Request / result                                                                     |
| -------------------- | ------------------------------------------------ | ------------------------------------------------------------------------------------ |
| GET                  | `/api/admin/pages`                               | Page ID, label, slug, status, revision, last editor and update time; filter/paginate |
| GET                  | `/api/admin/pages/:pageId`                       | Schema version, section schema, draft and published revision                         |
| PUT                  | `/api/admin/pages/:pageId/draft`                 | `{ baseRevision, sections }`; validate and return new draft revision                 |
| POST                 | `/api/admin/pages/:pageId/preview`               | `{ draftRevision }`; return private expiring preview URL                             |
| POST                 | `/api/admin/pages/:pageId/publish`               | `{ draftRevision, basePublishedRevision }`; atomically publish reviewed content      |
| GET                  | `/api/admin/pages/:pageId/revisions`             | Paginated revision history and authors                                               |
| POST                 | `/api/admin/pages/:pageId/restore`               | `{ revisionId }`; create a new draft, do not auto-publish                            |
| GET / POST           | `/api/admin/collections/:collection`             | Search/filter/list or create a record                                                |
| GET / PATCH / DELETE | `/api/admin/collections/:collection/:id`         | Read, edit or archive; reject invalid references                                     |
| POST                 | `/api/admin/collections/:collection/:id/publish` | Publish a reviewed record revision                                                   |
| GET / POST           | `/api/admin/media`                               | Search assets or multipart upload; durable asset record                              |
| PATCH / DELETE       | `/api/admin/media/:id`                           | Metadata or archive; report usages before removal                                    |
| GET                  | `/api/public/pages/:slug`                        | Published page content only, cacheable with revision/ETag                            |
| GET                  | `/api/public/collections/:collection`            | Published records only; controlled public collections                                |

Example draft payload (IDs must remain stable when reordered):

```json
{
  "baseRevision": 12,
  "sections": [
    {
      "id": "hero",
      "type": "hero",
      "visible": true,
      "order": 0,
      "content": {
        "headline": "Expertise across sectors.",
        "media": { "assetId": "asset_123", "alt": "Sentinel Africa conference" },
        "primaryAction": { "label": "Start training", "href": "/training/" }
      }
    }
  ]
}
```

Page records need `id`, `slug`, `schemaVersion`, `draftRevision`, `publishedRevision`, `updatedAt`, `updatedBy`. Collection records need stable IDs, status, order and timestamps. Media records need `id`, `url`, `mimeType`, `size`, dimensions/duration, alt text and usage references. Replace prototype URL strings with asset references and resolve URLs on public reads.

## Inbox, account and transaction API

| Method        | Endpoint                        | Responsibility                                              |
| ------------- | ------------------------------- | ----------------------------------------------------------- |
| GET           | `/api/admin/inbox/:kind`        | Paginated search/status/assignment filters                  |
| GET / PATCH   | `/api/admin/inbox/:kind/:id`    | Detail, assignment, status and private notes                |
| POST          | `/api/public/submissions/:kind` | Validated enquiry, feedback, application or booking request |
| POST / DELETE | `/api/admin/session`            | Sign in / sign out                                          |
| GET           | `/api/admin/session`            | Current identity and permissions                            |
| GET / POST    | `/api/admin/staff`              | Accounts / invite staff                                     |
| PATCH         | `/api/admin/staff/:id`          | Roles and account state                                     |

`kind` is an allowlisted enum: enquiries, feedback, job-applications, talent-applications, bookings. Shop orders must be created/updated from checkout and verified payment events, not arbitrary browser status changes. Payment integration needs a separate contract; this prototype does not process payments or send emails.

## Required integration behavior

1. Edit a published record without altering the currently public revision.
2. Save draft and show saved time, author and revision only after success.
3. Review the exact revision being published. Warn about unsaved changes.
4. Publish atomically and refresh public content/cache or trigger the static deployment pipeline.
5. Handle 401 authentication, 403 permissions, 409 revision conflicts, 413 file size and 422 field validation separately. Preserve user input after errors.
6. Persist uploads before publication. Temporary browser blob URLs are preview-only and must never enter published production content.
7. Validate destinations, required headings, image alt text, event date/time zones and collection references. Use server-side validation even when the frontend validates.
8. Test navigation from every sidebar entry, deep links and browser history; draft isolation; publication permissions; stale revision conflicts; private data access; and public refresh after publication.

## Prototype review checklist

- Open `/admin/#content-map` and follow a page link.
- Select a specific inner page and section; confirm the URL and heading agree.
- Change text, save draft, reopen the editor and confirm persistence.
- Review saved content, confirm prototype publish, inspect local history.
- Verify the homepage reflects published releases in this browser after refresh, while drafts appear only in Preview. Verify a separate browser retains the original content.
- Create a testimonial or logo inside its homepage section; verify the same draft appears in the shared content library.
- Preview Hero and each section before saving; verify the snapshot does not publish changes.
- Review the mobile sidebar and section outline in a browser before frontend sign-off.

### Client testimonial submission

The homepage invitation opens `TestimonialSubmission.tsx`. The prototype stores submissions under `sentinel-testimonial-submissions` with name, role, email, quote, consent, createdAt and pending-review status. It does not send data or publish a testimonial. Production should POST these fields to `/api/public/testimonials`, return a receipt, and expose pending entries through `/api/admin/inbox/feedback`. Staff review and consent verification must precede creating a published testimonial; email stays private.
